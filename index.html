Import without losing the lesson

  1. Import sales.csv on a sheet named Sales and products.csv on Products. Put headers in row 1. Use comma as the delimiter, UTF-8, a period as the decimal separator and English formula names. In Google Sheets set File > Settings > Locale to United States before importing and using VALUE. In Excel Power Query use a dot-decimal locale, such as English (United States), for numeric conversion; if the workbook's VALUE function expects comma decimals, normalize numeric text using the matching locale or Excel NUMBERVALUE with an explicit period decimal separator. Changing formula argument separators alone does not change numeric parsing. Prices are USD; 0.10 is a 10% discount. Import order/product IDs as text and units/prices/discounts as numbers.
  2. Follow exercises.md. It specifies date conversion rather than relying on a machine's locale. Formulas use commas; locales using semicolons may require separator changes. Excel for Microsoft 365 and Google Sheets are the target engines. Exact-match VLOOKUP alternatives are included for older Excel.
  3. Import all columns of messy-sales.csv as text on Messy to preserve the intended problems. In Excel use Data > From Text/CSV > Transform Data, remove automatic Changed Type if present and set all columns to Text. In Sheets use File > Import and turn off Convert text to numbers, dates, and formulas. Opening a CSV by double-click can silently convert dates and lose this lesson.
  4. Check your results against answers.csv and solutions.md. Instructors can withhold those files, defects.csv and sales.csv during the cleaning section.

Keep the raw export. The messy file deliberately contains 29 altered cells and four appended exact copies. Two missing values and one impossible date require supplied ground truth. Flag them before repairing them.

Calculation convention

For a Completed order, net sales are ROUND(units * unit_price_usd * (1 - discount_rate), 2). Returned and Cancelled orders contribute zero. Round each line to cents before summing. The worked solution uses integer price cents and whole-percent discounts, then rounds to the nearest cent before converting back to USD. This avoids binary floating-point noise at half-cent boundaries for this dataset. This simple convention excludes taxes, shipping, payments, return cash flows and costs. It is not an accounting model.

Ten exercises with worked solutions

Use Sales!A1:I145, Products!A1:D7 and Messy!A1:I149. Headers count as row 1. Keep totals outside source ranges. Fill formulas down to row 145 on Sales or row 149 on Messy. Each solution opens independently.

1Exercise 1: Import and validate dates

Import the clean files using the README rules. In Sales K1 enter parsed_date. Convert every Sales B date into a real spreadsheet date in K, whether B arrived as text or a date serial. Verify that K is numeric, then report the record count, minimum date and maximum date. Display dates as yyyy-mm-dd. Do not use DATEVALUE with an unspecified locale.

Show worked solution for exercise 1

Sales K2: =IF(ISNUMBER(B2),B2,DATE(VALUE(LEFT(B2,4)),VALUE(MID(B2,6,2)),VALUE(RIGHT(B2,2))))

Use =COUNTA(A2:A145) for 144 records, =COUNT(K2:K145) for 144 numeric dates, =MIN(K2:K145) for 2026-01-01 and =MAX(K2:K145) for 2026-03-31. Format K and the minimum/maximum result cells as dates. These checks use the clean file; exercise 9 adds calendar validation for defective dates.

2Exercise 2: Calculate completed net sales

In Sales J1 enter net_sales_usd. In M and N create integer unit-price cents and whole discount percentages from G and H. Use those helpers to calculate one amount per order in J using the stated status and line-rounding convention. Return the total net sales and the count of Completed orders. Explain why returned and cancelled units do not belong in the completed-sales amount.

Show worked solution for exercise 2

Sales M1: unit_price_cents; M2: =ROUND(G2*100,0).

Sales N1: discount_percent; N2: =ROUND(H2*100,0).

Sales J2: =IF(I2="Completed",ROUND(F2*M2*(100-N2)/100,0)/100,0)

=SUM(J2:J145) gives USD 6136.66. =COUNTIF(I2:I145,"Completed") gives 114. Fill both helpers before the net formula. All prices have two decimals and discounts are whole percentages, so integer cents make this dataset's half-cent rounding explicit and avoid floating-point boundary differences. For example, ORD-0070 is exactly USD129.675 before rounding and USD129.68 after rounding. A different dataset with fractional-cent prices or fractional-percent discounts needs a revised precision policy. Returned and Cancelled rows contribute zero under this pack's explicit convention.

3Exercise 3: Count returns with COUNTIF

How many orders have status Returned? Count orders, not units, and use a bounded source range. Check that Completed + Returned + Cancelled counts equal the clean record count.

Show worked solution for exercise 3

=COUNTIF(Sales!I2:I145,"Returned") gives 11 orders. The three status counts sum to 144. Counting F's units would answer a different question.

4Exercise 4: Apply two SUMIFS criteria

What is net sales for orders in the North region and Online channel? Include both conditions in the same formula and sum the net column from exercise 2.

Show worked solution for exercise 4

=SUMIFS(Sales!J2:J145,Sales!C2:C145,"North",Sales!D2:D145,"Online") gives USD 340.73. The criteria are combined with AND.

5Exercise 5: Use date boundaries in SUMIFS

What is February 2026 net sales? Use K's numeric dates from exercise 1, with a start date inclusive and the next month's first day exclusive. Explain why filtering by the text “February” is unreliable.

Show worked solution for exercise 5

=SUMIFS(Sales!J2:J145,Sales!K2:K145,">="&DATE(2026,2,1),Sales!K2:K145,"<"&DATE(2026,3,1)) gives USD 1786.52. K must hold numeric dates, not date-looking text. The exclusive March boundary also works if the source is later extended to timestamps.

6Exercise 6: Join the catalog by an exact key

Return P004's product name. Then add category in Sales L using product_id and the Products lookup table. Flag missing matches as Unmapped, count them and calculate net sales for the Office category. Do not assume either table is sorted the same way.

Show worked solution for exercise 6

=XLOOKUP("P004",Products!$A$2:$A$7,Products!$B$2:$B$7,"Unmapped",0) returns USB cable. Older Excel: =IFNA(VLOOKUP("P004",Products!$A$2:$D$7,2,FALSE),"Unmapped").

Sales L2: =XLOOKUP(E2,Products!$A$2:$A$7,Products!$C$2:$C$7,"Unmapped",0)

Older Excel: =IFNA(VLOOKUP(E2,Products!$A$2:$D$7,3,FALSE),"Unmapped"). =COUNTIF(L2:L145,"Unmapped") is 0. =SUMIFS(J2:J145,L2:L145,"Office") gives USD 2178.23. Validate uniqueness of Products' six keys first. A first-match lookup cannot safely resolve conflicting duplicate catalog keys.

7Exercise 7: Clean invisible spaces

On Messy J1 enter clean_region. Use TRIM and SUBSTITUTE with CHAR(160) so both ordinary spaces and nonbreaking spaces are removed. In K compare raw C with cleaned J using EXACT, returning 1 when changed and 0 otherwise. How many cells change? How many regions remain missing? Never invent a replacement region.

Show worked solution for exercise 7

Messy J2: =TRIM(SUBSTITUTE(C2,CHAR(160)," "))

Messy K2: =IF(EXACT(C2,J2),0,1). =COUNTIF(K2:K149,1) gives 7 changed cells. =COUNTBLANK(J2:J149) gives 1 unresolved region. TRIM by itself does not remove a nonbreaking space. The blank is ORD-0044 and must remain visible.

8Exercise 8: Find extra duplicate occurrences

On Messy L1 enter duplicate_after_first. Flag an order ID with 1 only when it has appeared earlier in column A, and 0 otherwise. Count the extra rows and the distinct IDs. Explain why testing COUNTIF across the full column > 1 counts eight affected rows rather than the four extra copies. Remove later copies only after confirming their other fields agree.

Show worked solution for exercise 8

Messy L2: =IF(COUNTIF($A$2:A2,A2)>1,1,0)

=COUNTIF(L2:L149,1) gives 4 extra rows. =COUNTA(A2:A149)-COUNTIF(L2:L149,1) gives 144 distinct IDs because there are no blank IDs. Appended copies are ORD-0008, ORD-0038, ORD-0079 and ORD-0120. A whole-range COUNTIF($A$2:$A$149,A2)>1 flags both copies, giving eight affected rows. Check all fields agree before keeping the first.

9Exercise 9: Import mixed dates without guessing

On Messy M:P create year, month, day and candidate date. Raw B contains YYYY-MM-DD, YYYY/MM/DD and DD/MM/YYYY; all slash dates with the year at the end are explicitly day-first. In Q create valid_date, returning 1 for valid and 0 for invalid, by comparing the candidate's YEAR, MONTH and DAY back to the extracted parts. Count invalid dates and valid raw rows before deduplication. Why is DATE alone insufficient for 2026-02-30?

Show worked solution for exercise 9

The following works on the raw text-preserving import. Four-digit years always occur at one end of the ten-character input. YYYY/MM/DD and YYYY-MM-DD use the same substring positions.

Messy M2 (year): =IF(OR(MID(B2,5,1)="-",MID(B2,5,1)="/"),VALUE(LEFT(B2,4)),VALUE(RIGHT(B2,4)))

Messy N2 (month): =IF(OR(MID(B2,5,1)="-",MID(B2,5,1)="/"),VALUE(MID(B2,6,2)),VALUE(MID(B2,4,2)))

Messy O2 (day): =IF(OR(MID(B2,5,1)="-",MID(B2,5,1)="/"),VALUE(RIGHT(B2,2)),VALUE(LEFT(B2,2)))

Messy P2 (candidate): =DATE(M2,N2,O2)

Messy Q2 (valid): =IF(AND(YEAR(P2)=M2,MONTH(P2)=N2,DAY(P2)=O2),1,0)

=COUNTIF(Q2:Q149,0) gives 1 invalid date; =COUNTIF(Q2:Q149,1) gives 147 valid raw rows including duplicates. ORD-0100 contains 2026-02-30. DATE silently normalizes it into March, so the round-trip validation is necessary. These fixed-position formulas are for the documented ten-character formats; unexpected formats should be flagged separately.

10Exercise 10: Reconcile the cleaned export

Make a separate Cleaned sheet. Normalize channel case, trim product IDs, convert padded units, remove the dollar prefix from prices and convert percent-text discounts. Preserve missing values as missing; flag the impossible date. Before using ground truth, report the number of missing required cells and the number of irrecoverable cells including invalid dates. Use the supplied clean record for only those three cells, record the repairs and remove the four later duplicate copies. Compare all nine fields by order_id with sales.csv. Recompute net sales and confirm the clean row count and total from exercise 2. A matching total alone does not prove each record is correct.

Show worked solution for exercise 10

Use the prior region/date helpers. Useful normalization formulas on a row copied from Messy are:

FieldFormula using raw row 2
channel=PROPER(TRIM(Messy!D2))
product_id=TRIM(Messy!E2)
units=IF(TRIM(Messy!F2)="","Missing",VALUE(TRIM(Messy!F2)))
unit_price_usd=VALUE(SUBSTITUTE(TRIM(Messy!G2),"$",""))
discount_rate=IF(RIGHT(TRIM(Messy!H2),1)="%",VALUE(SUBSTITUTE(TRIM(Messy!H2),"%",""))/100,VALUE(TRIM(Messy!H2)))

For these files, =COUNTBLANK(Messy!C2:C149)+COUNTBLANK(Messy!F2:F149) gives 2 missing required cells. Together with the invalid date there are 3 irrecoverable cells. This targeted count is valid because defects.csv specifies which required fields can be missing; a general import pipeline should check every required field.

Repair only ORD-0044 region (East), ORD-0067 units (7) and ORD-0100 date (2026-03-03) from the provided ground truth, and log those corrections. Remove four later duplicate rows and order the remaining data by order_id. Reconcile exactly 144 IDs and all nine fields against sales.csv, allowing equivalent typed numeric/date representations. Recomputed completed net sales must be USD 6136.66. Compare record-level fields and status counts as well as totals.

The standard-library generator computes cents using Decimal with half-up rounding. The companion verification script checks the saved CSVs independently. The local spreadsheet-engine checks evaluate the formulas for import, totals, filtered sales, exact lookup, whitespace, duplicates and date validation. What the messy file contains

There are 29 altered cells and four appended exact-copy rows. The manifest identifies five region cells with ASCII padding, two with nonbreaking spaces (U+00A0), three lowercase channels, two padded product keys, three padded unit counts, three dollar-prefixed prices, two percent strings, three YYYY/MM/DD dates, three explicitly DD/MM/YYYY dates, two missing required values and one impossible date (2026-02-30). Groups use different orders. Four unchanged orders are repeated at the end.

Two missing values and the impossible date cannot be recovered from the defective export alone. Flag them for review. The supplied clean table provides ground truth for this exercise; real data would require a source-system correction. Do not guess or turn missing units into zero. The messy schema intentionally treats fields as strings and has no unique primary-key constraint.

Provenance and reproducibility

Created on 11 October 2026 for this teaching pack. generate.py creates these rows from a fixed seed (20261011) using a documented integer generator; it does not download or copy any external dataset. Run python generate.py followed by python verify.py with Python 3.10 or later. The generator rewrites the six CSV files, Markdown teaching documents, metadata and checksums.sha256 in this folder. The independent verifier reads the saved files, checks the answer controls and reconciles the defective export. CSV files use UTF-8 without a BOM, LF line endings and standard CSV quoting. Preserve IDs when sorting and compare rows by ID, not their current positions.
