Why a sales subtotal changes after CSV cleaning

This interactive exercise uses 18 rows from an original fictional shop-sales teaching pack: 17 distinct order IDs and one repeated row. Turn preparation steps on separately and explain which records enter a selected subtotal. You will also see problems that automatic cleanup cannot resolve.

Start with West / All and all three controls off. Predict the subtotal after trimming category spaces, then after parsing known numeric formats. Try North / Wholesale to test whether capitalization affects a SUMIFS match.

Method and provenance

The FormulaSmith project created the original Synthetic Shop Sales: Spreadsheet Import and Cleaning Practice pack on 11 October 2026 using a deterministic generator with seed 20261011. These are wholly fictional transactions. No customer data or external dataset was used. This notebook embeds an unchanged excerpt from the pack's messy export, retaining original order IDs and data-row numbers. The exact original data rows after the header are 7, 8, 11, 13, 19, 21, 24, 29, 31, 34, 44, 52, 67, 100, 109, 112, 138, 145. Row 145 is an extra exact copy of ORD-0008. The complete original pack has 144 clean transactions and 148 messy rows. The excerpt contains 18 rows and must not be compared with full-pack totals.

For a Completed line, stage net sales are units × USD unit price × (1 − discount), rounded to the nearest cent before summing. Returned and Cancelled lines contribute zero. The demonstrator uses integer price cents and whole-percent discounts to avoid binary half-cent errors. It accepts only documented numeric formats, preserves blanks, validates dates without rollover, flags repeated IDs, and never substitutes the clean source's missing values. Date text written as DD/MM/YYYY uses that explicit source convention. No market or accounting conclusion is intended.
